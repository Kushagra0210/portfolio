## The problem

Solving a problem once is not the same as retaining the pattern. Notes and bookmarks record what happened, but they do not answer the operational question: **what should I revise today?** I built this as a personal system for converting solved questions into a clear, repeatable queue.

## Architecture

The repository is a single Next.js application, but the boundaries are deliberate: server-rendered routes expose the product, server actions and route handlers own mutations, domain services calculate revision state, and PostgreSQL holds the durable record.

## Ownership

This is a solo project. I own the product rules, schema, authentication, implementation, interface and tests. That makes it the clearest example of how I make trade-offs when there is no hand-off boundary to hide behind.

## Implementation details

The product includes an active-recall flow, overdue queue, searchable library, calendar, configurable intervals, streaks and keyboard shortcuts. Form input is validated before reaching the database. The schema separates a problem from its revision attempts so history remains useful when a schedule changes.

<Callout label="Backend signal">The interesting part is not the dashboard count. It is the invariant behind it: the same attempt history should produce the same due queue regardless of where the request runs.</Callout>

## Testing

Vitest covers scheduling and date behavior at the domain layer. Database integration tests exercise persistence and user isolation. These tests focus on expensive failure modes—incorrect due dates, cross-user access and mutation state—rather than treating component snapshots as proof of correctness.

## Limitations

- The interval model is fixed-step, not a learned retention model.
- Importing problem history from coding platforms is not automated.
- The deployed entry point requires an account, so recruiters cannot inspect private product data anonymously.

## Status

The application is live and actively usable. Next improvements are an onboarding sample workspace, data export and a richer review-quality signal without turning the system into a gamified leaderboard.
