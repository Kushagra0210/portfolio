## The problem

RTO services are not a single form. They are long-running workflows involving identity, eligibility, documents, payments, appointments, status changes and recovery when something goes wrong. RaahSathi explores how that complexity can become a clearer bilingual product journey.

## Architecture

RaahSathi is collaborative work. The application uses Next.js for the product surface and server layer, Prisma with PostgreSQL for durable workflow state, and validation and test tooling around service boundaries.

## Implementation details

My changes span server and client boundaries: session handling, Prisma-backed application state, API validation, appointment and waitlist behavior, payment state, responsive navigation and reviewer-oriented interface states. That breadth mattered because failures in one layer surface as confusion in another.

## Testing

The repository uses Vitest for focused logic and service tests and Playwright for browser-level flows. I added tests around backend behavior and workflow hardening, especially where a retry or recovery path could corrupt state.

## Limitations

- This is a product prototype, not an official government service.
- Payment behavior is an application workflow demonstration, not a production financial integration.
- Service rules and document requirements need jurisdiction-specific verification before real-world use.

## Status

The service catalogue is deployed. The strongest next step would be a seeded reviewer account and a documented end-to-end demo path for one representative service.
